# Voucher ownership details (#83)

Implemented on `feat/scoped-voucher-details`, based on main `3601eb1`. This document records implementation and automated evidence, not a deployment or production acceptance claim.

## Staff policy

| Staff role | Voucher rows/details/counts/export | Voucher codes | Customer name/account phone | Payment reference/payer phone | Voucher mutation |
| --- | --- | --- | --- | --- | --- |
| Owner | All | Yes | Yes | Yes | Existing owner permissions |
| Operator | All | Yes | Yes | Yes | Existing operational permissions |
| Reseller | Explicitly assigned stock, otherwise stock generated by this staff ID | Own scope only | Denied | Denied | Generate unassigned resale stock only |
| Auditor | All operational voucher records, read only | Denied | Denied | Denied | Denied |

An explicit `assignedResellerId` takes precedence over `generatedByAdminId`. The legacy boolean `generatedByAdmin: true` does not identify a reseller and cannot grant scope. New generated stock records the authenticated generator, and reseller generation records self-assignment. No new role/contact permission grant or assignment-editing workflow is introduced. A missing/disabled staff user loses access; current user roles are checked instead of trusting an old session role. Unknown roles cannot read voucher/business routes. Existing notification-only viewer preferences remain compatible.

Restricted roles cannot enumerate contacts/payments through generic customer/payment/session/raw event/audit records or network setup/report endpoints. Operational Wi-Fi records are scoped to readable vouchers and explicitly projected. Dashboard voucher counts and router observations use the same scope; global payment/security/queue payloads are excluded. Restricted staff still see public bundle prices and the sale classification/face value of readable stock; these are voucher inventory fields, not payment/contact permission.

## API and UI

`GET /api/admin/vouchers/:id/details` checks the current active staff user, role and voucher scope on every request. An unauthorized ID and a missing ID both return the same 404. `?checkScope=1` returns only the authorized exact ID and current scope marker, allowing the browser to revalidate a delayed response before rendering contacts. These requests are read only, use the existing response-buffered transaction boundary, and return `Cache-Control: no-store`.

Responses whitelist voucher lifecycle/balance fields, a small plan projection, ownership state, permitted current customer name/account phone, and permitted payment fields. Payer phone is separately labelled and never used to infer ownership. An unassigned voucher says **Not linked yet**. An orphaned customer relationship says **Linked account unavailable**. Credentials, security/recovery state and future arbitrary object fields are excluded.

Voucher list/count/search/date/status/page results and CSV export use the same policy. A protected phone, payment ID or restricted code cannot be used as a search oracle. Filtered exports include every matching authorized row, independent of the requested UI page. CSV cells are quoted and spreadsheet-formula prefixes escaped. Existing copy/generated CSV functionality and customer PDF download routes retain their authorization; reading details adds no mutation rights. The old revoke handler now requires POST, closing a GET mutation bypass.

The compact row has an accessible Details button with `aria-expanded`/`aria-controls`, a labelled region, local loading/retry and an explicit refresh. Expanded contents are discarded on collapse, filtering/page replacement, logout, authorization failure and backgrounding. Request versions, aborts, exact row IDs, scope markers and a current authority check prevent delayed replies from filling another row or a demoted user's panel. Reopening/refreshing obtains current account information. A 15-second visible-page refresh preserves panels and focus when rows remain authorized; no contact response is stored in browser storage. Already delivered data cannot be retroactively recalled from a browser's network inspector.
